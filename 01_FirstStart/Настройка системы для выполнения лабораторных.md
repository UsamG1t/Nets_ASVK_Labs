# Вступление

Лабораторная работа представляет из себя практико-ориентированную пошаговую инструкцию, выполняемую на одной или нескольких виртуальных машинах. В домашнее задание входит настройка некоторой топологии сети, её конфигурация и сбор этих данных в отчёт специального вида с помощью встроенных в виртуальные машины утилит.

В качестве менеджера виртуальных машин используется [VirtualBox](https://www.virtualbox.org/), система для выполнения лабораторных предоставляется в виде [архива с виртуальной машиной](https://drive.usercontent.google.com/download?id=1NGCXB53m4syTGiH_FMkQStTha6CD_Q0A&authuser=0) (Open Virtual Appliance, `.ova`-файл), на основе которого будет создана основная система, на её основе будут создаваться копии для работы.

⚠ ***ВАЖНО:*** Некоторые команды для Windows или для разных процессоров могут отличаться. Данные команды будут помечены в лабораторных специальных значком ![](../01_FirstStart/Attached_materials/alientech32.png)

# Настройка виртуальных машин

В данной главе описаны основные действия и / или команды, необходимые для работы с `VirtualBox`.

ℹ `VirtualBox` поддерживает собственный набор команд для работы из терминала с помощью встроенной утилиты `VBoxManage`, полный список команд представлен по команде `VBoxManage --help`. Также все настройки над виртуальными машинами возможно проводить через графическую оболочку. Данные способы настройки представлены в [отдельном разделе](../Additional/Old_Settings.html).

Для настройки ВМ в данных лабораторных используется пакет [PySnap](https://usamg1t.github.io/NeuroPysnap/).

⚠ ***Важное примечание:*** В ранних версиях `VirtualBox` при работе из консоли использовалась локализация внутренних настроек, из-за чего переведённые файлы настроек **не работали**. При работе используйте латинские названия, перед работой _рекомендуется_ менять локаль с помощью команды `export LC_ALL=C`

# Импорт образа и создание виртуальных машин

ℹ Для выполнения лабораторных необходимо единожды импортировать образ диска и после создавать клоны для работы.

📍 1. Скачайте последнюю версию пакета `Pysnap` с [официальной страницы](https://usamg1t.github.io/NeuroPysnap/index.html)

📍 2. Установите пакет в вашу систему или в виртуальное окружение Python:

```console
[papillon_rouge@localhost ~]$ python3 -m venv .pysnap
[papillon_rouge@localhost ~]$ source .pysnap/bin/activate
(.pysnap) [papillon_rouge@localhost ~]$ pip install Downloads/pysnap-2.1.0-py3-none-any.whl
Processing ./Downloads/pysnap-2.1.0-py3-none-any.whl
…
Successfully installed prompt_toolkit-3.0.53 pysnap-2.1.0 pyte-0.8.2 wcwidth-0.8.2
(.pysnap) [papillon_rouge@localhost ~]$
```

ℹ В дальнейшем для работы с утилитой необходимо будет просто активировать окружение.

```console
[papillon_rouge@localhost ~]$ source .pysnap/bin/activate
(.pysnap) [papillon_rouge@localhost ~]$
```

📍 3. Импортируйте установленный образ с помощью команды `pysnap import`. Используйте короткое имя для переименования образа:

```console
(.pysnap) [papillon_rouge@BaseALT-Papillon ~]$ pysnap import Downloads/protocols-jeos-x86_64.ova SmallName
Importing [################################] 100%
Imported virtual machines:
- SmallName (/LinuxNetwork2026)
(.pysnap) [papillon_rouge@BaseALT-Papillon ~]$
```

📍 4. _Перед_ клонированием настройте базовую ВМ для работы с помощью команды `pysnap protosettings`:

```console
(.pysnap) [papillon_rouge@BaseALT-Papillon ~]$ pysnap protosettings SmallName
Registered proto-settings VM: SmallName
Configured proto-settings VMs: SmallName
(.pysnap) [papillon_rouge@BaseALT-Papillon ~]$
```

📍 5. Для клонирования машины используйте команду `pysnap clone`. Укажите базовую ВМ и имя для клона:

```console
(.pysnap) [papillon_rouge@BaseALT-Papillon ~]$ pysnap clone SmallName CloneVM
Name: CloneVM
Group: /LinuxNetwork2026
Serial port: 2331
Parent VM: SmallName
(.pysnap) [papillon_rouge@BaseALT-Papillon ~]$
```

Поздравляем с созданием вашей первой рабочей машины!

# Подключение к виртуальным машинам

После создания виртуальных машин необходимо их включить и к ним подключиться. Обычный запуск виртуальных машин автоматически открывает эмулятор экрана виртуальной машины, установленный в VirtualBox. Однако из-за особенностей настройки он не позволяет производить копирование из основной системы в интерфейс виртуальной машины и, соответственно, копировать данные между виртуальными машинами с помощью буфера обмена.

При работе через Pysnap воспользуйтесь командой `pysnap connect` для подключения к ВМ:

```console
(.pysnap) [papillon_rouge@BaseALT-Papillon ~]$ pysnap connect CloneVM
```

# Работа с командной строкой

ℹ В процессе выполнения лабораторных работ необходимо проводить настройку виртуальных машин через терминальный интерфейс. Рассмотрим команды и работу с терминалом на примере тестовой машины.

📍 1. Запустим виртуальную машину. Для входа в систему каждой машины необходимо вводить логин (`root`) и пароль (`root`).

⚠ ***ДИСКРЕЙМЕР:*** Никогда не устанавливайте такие легко угадываемые пароли на свои персональные устройства!

⚠ ![](../01_FirstStart/Attached_materials/alientech32.png) В некоторых случаях виртуальная машина может сразу не запуститься. Для работы необходимо отключить встроенную в ядро специальную поддержку виртуализации. В случае Linux необходимо в командной строке выполнить команду `sudo rmmod kvm_amd`, в случае Windows — запустите командную строку _от имени администратора_, выполните команду `bcdedit /set hypervisorlaunchtype off` (убедитесь, что ответное сообщение терминала `<Smth> completed successfully`; Иначе выполните действия из [данной статьи](https://learn.microsoft.com/ru-ru/troubleshoot/windows-client/application-management/virtualization-apps-not-work-with-hyper-v)) и перезапустите устройство.

⚠ ![](../01_FirstStart/Attached_materials/alientech32.png) Виртуальная машина в случае проблем с виртуализацией может загружаться от 20 секунд вплоть до 10 минут, при этом демонстрировать как будто постоянную перезагрузку.

📍 2. Для переименования виртуальной машины используется специальная команда `sethostname` (при смене имени виртуальной машины требуется повторный вход в систему). С помощью данной команды переименуйте ВМ.

`@srv`

```console
localhost login: root
Password:
[root@localhost ~]# sethostname srv

Password:

[root@srv ~]#
```
